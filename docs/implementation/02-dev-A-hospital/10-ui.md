# 02-10 — hospital-ui: Desk, Officer and Admin Screens (Next.js 14)

Status: PROPOSED. Owner: Dev A. Code: `hospital/ui/` (Next.js 14 App Router, TypeScript strict, Tailwind, shadcn/ui, TanStack Query, react-hook-form + zod, Playwright, Vitest, MSW). Port 3000.

## 1. Goal
A usable, role-aware web UI for hospital staff: create and track claims, upload documents with live processing feedback, resolve completeness gaps, review/edit/sign off claim drafts, answer insurer queries, and administer configuration, with a real-time status feed via SSE.

Design stance:
- **Presentation only.** No business rules in the client beyond light validation; the API is authoritative and the UI surfaces its errors.
- **Fixable before fatal.** Every blocking state shows what to do next, with a shortcut action (upload this doc type, answer this query).
- **Human authority.** Sign-off, query approval and config publish are explicit, confirmed, audited actions.
- **Evidence visible.** Anywhere data came from a document, the UI offers a jump to the source page.

## 2. Inputs / Outputs
- In: hospital-api REST (`/v1/*`), SSE stream, Keycloak OIDC.
- Out: user actions as API calls; no persistent client-side business state.

| Persona | Role claim | Main jobs |
|---|---|---|
| Desk staff | `desk` | create cases, upload docs, fix checklist gaps |
| Claims officer | `officer` | review/edit claim, sign off, submit, answer queries, waive items |
| Admin | `admin` | config versions, users, outbox, audit |

## 3. Data model (client types)
Generate TypeScript types from `hospital/api/openapi.json` with `openapi-typescript`; wrapper `lib/api.ts` (fetch + typed paths + problem-JSON error mapping). No duplicated enums: import from generated types.

Key client-side view models (`lib/types.ts`, derived not duplicated):
```ts
type CaseRow = components["schemas"]["CaseSummary"];
type DocStatusChip = "scanning" | "quality" | "parsing" | "classified" | "needs_review" | "failed" | "blocked";
interface UiEvent { id: string; type: string; case_id?: string; payload: unknown; ts: string }
interface ApiProblem { status: number; code: string; title: string; detail?: string; errors?: {field:string; message:string}[]; trace_id?: string }
```
Mapping `parse_status` + `scan_status` → `DocStatusChip` lives in one pure function `lib/docStatus.ts` (unit tested; the UI never infers business state beyond display).

State management: server state in TanStack Query (keys `["case", id, "documents"]`, `["case", id, "checklist"]`, `["case", id, "claim"]`, `["queries", filters]`, `["config", domain]`); UI-only state in component state or URL search params (filters, tabs, pagination cursor) so views are shareable.

### 4.1 Screen specs

#### S1 Login and session
- Components: `LoginPage` (single "Sign in" button), `SessionGate` (server component wrapper).
- States: unauthenticated → redirect to Keycloak; callback error → message with "try again"; session expired → return-URL preserved.
- API: none (NextAuth); roles from token claim `realm_access.roles`.

#### S2 Dashboard `/`
| Widget | Data | API |
|---|---|---|
| Status tiles (draft, docs pending, ready, submitted, under query, decided) | counts | `GET /v1/dashboard/summary` |
| My queue | cases assigned to me needing action | `GET /v1/cases?assignee=me&needs_action=true` |
| Deadline warnings | reimbursement filing window, query SLA | `GET /v1/dashboard/deadlines` |
| Overdue items | docs requests past due | same summary |
- Empty state: "Nothing needs your attention".
- Loading: skeleton tiles. Error: inline retry card.
- Tiles are links to pre-filtered `/cases`.

#### S3 Cases list `/cases`
- Components: `CaseFilters` (status multi-select, claim type, assignee, date range, free text), `CaseTable` (columns: claim ref, patient, claim type, status chip, route chips, deadline, updated), `SavedViews` (stored via API user prefs).
- API: `GET /v1/cases?status=&claim_type=&assignee=&q=&cursor=&limit=25` (keyset pagination).
- Behaviours: filters in URL; row click → `/cases/[id]`; bulk actions none in v1; "New case" button for desk/officer.
- States: loading skeleton rows; empty ("No cases match"); error banner.
- SSE: `case.status_changed` patches the row in cache.

#### S4 New case stepper `/cases/new`
Steps:
1. **Patient:** name, DOB, gender, member id, phone (masked after save). zod mirrors server rules; DOB not in future.
2. **Policy:** insurer (select from `network_insurer`), policy number, TPA card number, policy validity hint.
3. **Admission:** admission type (planned/emergency), admitted on, diagnosis (free text + ICD search), treating doctor, pre-auth ref (cashless).
4. **Claim type:** radio cashless/reimbursement; router suggestion banner from `POST /v1/cases/route-preview` with reasons; override requires officer role and reason.
- Submit `POST /v1/cases` (with `Idempotency-Key`); on 422 map `errors[].field` to form fields; on success go to `/cases/[id]/documents`.
- Draft autosave to sessionStorage (try/catch) only; no PII in localStorage.
- Emergency admission shows banner "Intimate insurer within 24 h" with countdown from admit time.

#### S5 Case workspace shell `/cases/[id]`
- Layout `layout.tsx` fetches case summary server-side; renders header (see above) + tab nav (Documents, Checklist, Claim, Submission, Queries, Timeline).
- Tabs visible by role (Claim editor for officer; read-only view for desk).
- Status stepper uses server `status`; deadline countdown from `deadlines` in response.
- Connection indicator: green (SSE connected), amber (reconnecting), grey (polling fallback).

#### S6 Documents tab
| Element | Behaviour |
|---|---|
| Dropzone | multi-file drag-and-drop, 25 MB cap, types pdf/jpg/png/tiff; optional doc-type preselect |
| Upload queue | concurrency 3, per-file progress (XHR), retry, cancel; duplicate (409/200 duplicate) shown as "Already uploaded" |
| Document grid | card per document: thumbnail, filename, doc type (editable select), status chip, quality flags overlay, page count |
| Status chips | Scanning → Quality → Parsing → Classified → Needs review / Failed / Blocked (infected) |
| Viewer (Sheet) | PDF.js pages lazy rendered, image zoom/rotate, extracted fields side panel with confidence badges |
| Actions | Reclassify (select + reason), Re-parse, Delete (desk before submission; officer after, with reason), Download (presigned) |
- API: `POST /v1/cases/{id}/documents` (multipart), `GET /v1/cases/{id}/documents`, `PATCH /v1/documents/{id}` (doc type), `POST /v1/documents/{id}/reparse`, `DELETE /v1/documents/{id}`, `GET /v1/documents/{id}/preview-url`.
- SSE: `doc.scanned`, `doc.quality`, `doc.parsed`, `doc.classified`, `doc.failed` update chips live.
- Failure text: Failed → "We could not read this file. Try re-parse or upload a clearer copy." Blocked → "File failed virus scan and was removed."

#### S7 Checklist tab
- Groups: Blockers (missing required), Needs attention (illegible, low confidence), Optional, Satisfied, Waived.
- Each row: requirement label, status icon + text, evidence (which document satisfies), "what to do" text from config, actions.
- Actions: "Upload now" (opens dropzone with doc type preselected), "Mark not applicable / waive" (officer; reason dialog), "Remind" (shows reminder log).
- Footer: overall status `complete / incomplete`, "Build claim" button enabled when `complete` (officer).
- API: `GET /v1/cases/{id}/checklist`, `POST /v1/cases/{id}/checklist/{req}/waive`, `GET /v1/cases/{id}/reminders`.
- SSE: `completeness.updated`.

#### S8 Claim editor `/cases/[id]/claim`
Layout: two panes.
- **Left:** form sections
  - Patient (read-only, from case), Admission (dates, diagnosis/ICD chips, procedures), Bill lines table (description, category select, qty, unit price, amount; add/remove/inline edit; Decimal-safe string inputs; row error badges), Totals (computed read-only: gross, discounts, claimed; mismatch warning).
- **Right:** document viewer; focusing a field jumps to its `source_doc_id/page` (provenance) and highlights the quote when bbox available.
- **Validation panel** (bottom or drawer): errors V-codes (blockers) and warnings (need acknowledge checkbox each); click item scrolls to field.
- **Header actions:** Save draft (autosave on blur, `PATCH` with `If-Match`), Version history (diff view), Return to builder (repair; confirms losing manual edits? shows diff), Sign off (disabled until no errors and warnings acknowledged), Submit (after sign-off; confirm dialog with summary, totals, attached documents count, deadline warnings).
- API: `GET /v1/cases/{id}/claim`, `PATCH /v1/cases/{id}/claim` (If-Match version), `POST /v1/cases/{id}/claim/validate`, `POST /v1/cases/{id}/claim/rebuild`, `POST /v1/cases/{id}/claim/sign-off`, `POST /v1/cases/{id}/claim/submit`.
- States: building (spinner with SSE progress "Assembling claim…"), draft ready, errors, signed-off (read-only with "Reopen" for officer), submitted (read-only).
- Conflict: 409 → dialog "Someone changed this claim" with "Reload latest" and field-level diff.

#### S9 Submission tab
- Timeline: queued → sent → acknowledged (insurer claim no) → status updates; attempt log table (attempt, time, HTTP status, message).
- Actions: Retry now (officer/admin) when dead-lettered; Withdraw claim (officer, confirm).
- Banner when unacknowledged > 15 min.
- API: `GET /v1/cases/{id}/submission`, `POST /v1/cases/{id}/submission/retry`, `POST /v1/cases/{id}/withdraw`.
- SSE: `submission.*`.

#### S10 Queries tab and inbox
Inbox `/queries`: tabs Open, Draft ready, Awaiting approval, Overdue; table with case, round, category chip, urgency, SLA countdown, owner; filters.
Thread view per case:
- Round cards (1-3) each with: insurer text, requested documents, triage chips (class, urgency), SLA countdown, status.
- **Draft editor:** textarea with citation chips (`[doc:page]` rendered as buttons opening viewer at page), grounding warnings highlighted (`unsupported_claims` underlined with tooltip), word counter (≤ 250 target), attachment picker (suggested attachments pre-checked) + upload new, "Regenerate draft", "Approve", "Send".
- Round counter badge; round-3 banner: "Final round, two-person approval required" with approver 1/2 status.
- Read-only after send; shows insurer follow-up.
- API: `GET /v1/queries`, `GET /v1/queries/{id}`, `POST /v1/queries/{id}/draft` (trigger), `PUT /v1/queries/{id}/response-draft`, `POST /v1/queries/{id}/approve`, `POST /v1/queries/{id}/send`.
- SSE: `query.new`, `query.draft_ready`, `query.updated`.
- Edge: user edits a draft while regenerate completes → show "newer draft available" banner, never overwrite silently.

#### S11 Admin: config editor `/admin/config/[domain]`
- Left: versions list (version, status chip, effective from, author). Right: editor.
- Table view for `doc_requirements` (rows by claim type/admission/procedure group, required/optional checkboxes) and `deadlines`; raw JSON view (Monaco lazy) with server JSON Schema validation.
- Buttons: Save draft, Validate (shows errors), Dry-run (shows diffs over N sample cases, counts of changed outcomes), Publish (second admin approval state "Awaiting approval by another admin"), Retire.
- API: `GET/POST /v1/admin/config/{domain}/versions`, `POST .../{v}/validate`, `.../{v}/dry-run`, `.../{v}/publish`, `.../{v}/approve`.
- Published versions are read-only; "Create draft from this" action.

#### S12 Admin users, audit, outbox
- Users: table, activate/deactivate, role display (Keycloak is source of truth; link out for role changes), last login.
- Audit explorer: case picker, timeline (actor, event type, time), filters, JSON viewer with redaction note, "Verify chain" button → badge (verified / broken at seq N). API: `GET /v1/audit/{case_id}?cursor=`, `POST /v1/audit/{case_id}/verify`.
- Outbox: dead-lettered messages table (claim ref, message type, attempts, last error), Retry, View payload (redacted). API: `GET /v1/admin/outbox`, `POST /v1/admin/outbox/{id}/retry`.

## 6. Key logic
- Optimistic updates only for harmless UI state; mutations on case data wait for server response and surface 409 (version conflict) with a "reload latest / see diff" dialog using `If-Match`.
- Status chips derive from server `status` + `parse_status`; client never infers business state.
- SSE event → cache invalidation map:
```ts
const invalidate: Record<string, (qc: QueryClient, e: UiEvent) => void> = {
  "doc.parsed": (qc,e)=>qc.invalidateQueries({queryKey:["case",e.case_id,"documents"]}),
  "doc.failed": (qc,e)=>qc.invalidateQueries({queryKey:["case",e.case_id,"documents"]}),
  "completeness.updated": (qc,e)=>qc.invalidateQueries({queryKey:["case",e.case_id,"checklist"]}),
  "claim.draft_ready": (qc,e)=>qc.invalidateQueries({queryKey:["case",e.case_id,"claim"]}),
  "submission.updated": (qc,e)=>qc.invalidateQueries({queryKey:["case",e.case_id,"submission"]}),
  "query.new": (qc)=>qc.invalidateQueries({queryKey:["queries"]}),
  "query.draft_ready": (qc,e)=>qc.invalidateQueries({queryKey:["queries", e.payload.query_id]}),
  "case.status_changed": (qc,e)=>{ qc.invalidateQueries({queryKey:["case",e.case_id]}); qc.invalidateQueries({queryKey:["cases"]}); },
};
```
- Toast policy: toast only for `claim.draft_ready`, `query.new`, `submission.failed`, `decision.received`; others silently refresh.
- SSE resilience:
```ts
function connect(){
  const es = new EventSource(`/api/stream?lastEventId=${lastId}`);
  es.onmessage = ev => dispatch(JSON.parse(ev.data));
  es.onerror = () => { es.close(); setState("reconnecting"); retry(backoff()); if(fails>3) startPolling(); };
}
```
  On reconnect, resync by invalidating all active queries once.
- Money: never `number` for amounts; `Decimal` from strings; display via `Money` component only.
- Role gating is UX only; the API enforces everything. Hidden actions are absent, not merely disabled, except Sign off/Submit which show disabled with reason tooltip.
- Masking: phone and ID last-4 by default; "Reveal" calls `POST /v1/cases/{id}/reveal` which logs an audit event, then shows for 30 s.

## 8. Error handling and edge cases
| Situation | Behaviour |
|---|---|
| 401 mid-session | silent refresh, otherwise redirect with return URL |
| 403 | page-level "You do not have access" with role hint |
| Upload of 30 files | queue concurrency 3; resume list on failure; per-file retry |
| SSE drops | banner "reconnecting", polling fallback, resync on reconnect |
| Large PDFs in viewer | lazy page rendering, 2-page window |
| Stale edit conflicts | diff dialog with field-level choice |
| Empty states | every list has empty state and loading skeleton |
| Offline | detection toast, disable mutating buttons |
| Sensitive data | mask phone and ID last-4 by default; "reveal" logs audit event |
| Browser support | latest Chrome/Edge/Firefox |
| Duplicate submission clicks | button disabled while pending; idempotency key |
| Server 500 | error card with trace_id copy button |
| Clock skew | countdowns use server `now` offset from response header `Date` |
| Time zones | display Asia/Kolkata, store UTC |
| Doc deleted while viewing | viewer closes with toast |
| Claim signed off while editing in other tab | 409 on save, reload prompt |
| Very long bill (200+ lines) | virtualised table |
| Draft contains unsupported claims | Send disabled until acknowledged or edited (API re-checks) |
| Missing insurer response docs | attachment picker shows doc types requested with "upload" shortcut |
