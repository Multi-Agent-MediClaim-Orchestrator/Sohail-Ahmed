# 03-10 — insurer-ui: Reviewer, Approver, Admin Screens (2.6)

Owner: Dev B. Status: PROPOSED. Container `insurer-ui` (Next.js 14 App Router, port 3100).
Depends on: insurer-api (docs 03-06), Keycloak realm `insurer`, SSE feed `/v1/events/stream` from insurer-api.

## 1. Goal
A fast, auditable workspace where Reviewers verify claims, Approvers decide above thresholds, Senior reviewers resolve escalations, and Admins manage policies, requirements, thresholds, users and audit. The UI calls **only insurer-api** (through a Next.js BFF proxy). It contains display logic and form validation only; **no business rules** (gate tier, payable amounts, completeness, eligibility are all computed server-side).

Principles:
1. Human authority: the UI presents the system recommendation and makes the human action explicit and deliberate.
2. Evidence first: every finding links to the document page and region that supports it.
3. Label AI: text produced by agents is visibly tagged "AI explanation — not used for gating".
4. Hide, but never trust: the UI hides actions the user lacks the role for; the server enforces regardless.
5. Privacy by default: member PII masked, reveals audited.

## 2. Inputs / Outputs
- Input: REST `/v1/*` with Keycloak access token (OIDC code + PKCE, tokens held server-side in an httpOnly cookie by the BFF), SSE `/v1/events/stream`.
- Output: user actions mapped 1:1 to API calls with `Idempotency-Key` and `If-Match` (ETag) headers on mutations.
- No direct calls to n8n, crew, calc-engine, rag-service or databases.

## 3. Data model (client types and state)
- Types generated from OpenAPI: `npx openapi-typescript <insurer-openapi-url> -o src/api/types.ts`, plus contract types from `contract/openapi/claims-v1.yaml` for shared enums (`InsurerCaseStatus`, `QueryStatus`, `DecisionOutcome`, `Severity`).
- Server state: TanStack Query. UI-only state (filters, pane sizes, selected doc/page): Zustand store persisted to `sessionStorage` (no PII).
- Roles (Keycloak realm roles): `reviewer`, `senior_reviewer`, `approver`, `admin`. A user may hold several. `approver` and `senior_reviewer` can approve; self-approval is blocked server-side.

### 3.1 Key client-side view models
```ts
type Workspace = {
  case: CaseSummary; etag: string;
  documents: DocItem[];                    // id, type, status(fetch/scan), pages, thumbnailUrl
  steps: StepResult[];                     // fetch, completeness, identity, authenticity, coverage, calculation
  findings: Finding[];                     // code, severity, fixable, evidence[], deterministic{score,threshold}, agentNote?
  calc: CalcResult | null;                 // lines, totals, ruleIds, traceId
  recommendation: Recommendation | null;   // outcome, amount, reasonCodes
  gate: { tier: 'auto'|'single'|'dual'; decidedBySystem: boolean; requiresSenior: boolean; approvedBy: UserRef[]; needed: number };
  queries: QueryThread[];                  // rounds 1..3
  sla: { dueAt: string; state: 'ok'|'breached' };
  assignee: UserRef | null;
  permissions: { canOverride: boolean; canDecide: boolean; canApprove: boolean }; // hints only
};
```
`permissions` from the API are hints for rendering; the UI also checks token roles.

### 4.1 Claim review workspace (`/cases/[id]`)
Three-pane layout with header and footer. Panes resizable (drag handles), collapsible on < 1280 px (tabs instead).

**Header bar**
- Claim no (`IC-YYYY-NNNNNN`), hospital claim ref, status chip, claim type chip (cashless/reimbursement), admission type chip.
- Member name masked (`R*** K****`) + "Reveal" button (audited).
- Amounts: claimed, recommended payable, delta.
- SLA timer (green/amber/red with tooltip of due date in IST, UTC on hover).
- Assignee dropdown (reviewer: self-assign; senior: reassign).
- "Also viewing: X" presence chip.
- Actions: Re-run verification (reviewer), Add note, Withdraw hold (senior).

**Left pane — Documents**
- List grouped by `doc_type`, each row: icon, filename, pages, fetch status (pending/ok/failed), scan status, parse confidence badge.
- Viewer: PDF.js canvas (`react-pdf`), page nav, zoom (fit width/page, 50-300%), rotate, thumbnails strip, text layer search.
- Evidence overlays: rectangles from finding evidence (`bbox` normalised 0..1), colour by severity; clicking an overlay scrolls the findings list to the finding.
- Compare mode: two viewers side by side (e.g. discharge summary vs final bill) with synchronised page option.
- Fallback: images (png/jpg) via `<img>` with same overlay layer; unsupported types download link.
- Shortcuts: `j/k` next/prev doc, `[` `]` prev/next page, `+ -` zoom.

**Center pane — Verification**
- Stepper: Fetch → Completeness → Identity → Authenticity → Coverage → Calculation, each with state chip (`pending|running|passed|warning|blocker|failed|skipped|degraded`) and duration.
- Each step is an accordion with:
  - Deterministic block: scores/thresholds table (e.g. name similarity 0.93 ≥ 0.85), rule ids, config version.
  - Findings list: severity chip, code, short message, fixable badge, "evidence" links (open doc/page/bbox), status (open/overridden/resolved), override button.
  - Agent notes: collapsible, labelled "AI explanation — not used for gating", shows model alias and Langfuse trace link (admin only).
  - Degraded banner if step ended with `agent_unavailable`: "Automated explanation unavailable; deterministic checks shown. Manual check required."
- Re-run step button (reviewer) with confirmation; running state is driven by SSE.

**Right pane — Decision**
- Claim summary card: policy no, product, sum insured, balance, waiting period status, preauth ref.
- Calculation breakdown table: columns line, category, claimed, disallowed, payable, rule ids (chips linking to trace drawer); totals row; filters (only disallowed, only flagged); virtualised for 200+ lines.
- Trace drawer: ordered calc steps (caps → sub-limits → co-pay → deductible) with intermediate amounts, `calc_engine_version`, `policy_rules_v`.
- Recommendation card: outcome (approve/partial/reject/needs_info), amount, reason codes, "Why" expandable (findings referenced).
- Gate banner: text from API, e.g. "Payable ₹6,20,000 > T_four. Requires 2 approvers including 1 senior." Never computed client-side.
- Decision form (see 6.3).
- Queries panel (see 4.2).
- Notes panel: internal notes (not sent to hospital) with author, timestamp.

**Footer**: audit tail (last 5 events, link to full audit), SLA, connection indicator (live/paused).

**Keyboard shortcuts** (global in workspace, disabled in inputs): `?` help, `j/k` doc, `[ ]` page, `f` toggle findings, `n` next open finding, `q` new query, `a` open approve dialog (role permitting), `r` re-run, `g c` go to cases list, `/` focus search.

### 4.2 Queries panel
- Thread per round (1, 2, 3) with round indicator "Round 2 of 3", due date, status chip (`open|draft_ready|answered|closed|escalated`).
- Draft view: category, text, requested doc types, citations (finding id, clause snippet, requirement text, expandable), lint results (tone, missing citation, over-length) with blockers disabling "Send".
- Edit: textarea with live counter (max 1200 chars), requested doc type multi-select, due-date picker bounded by `query_policy`.
- Send: confirmation modal summarising what hospital will see. Sent query becomes read-only; "Withdraw" allowed until answered (senior).
- Responses: hospital reply text, attached docs (opens in left-pane viewer), triage verdict (addressed/unaddressed items), "Override triage" (senior) with comment.
- Round 3 unresolved: escalation badge and link to escalation.

## 6. Key logic / pseudocode

### 6.1 Workspace data loading
```tsx
const ws = useQuery({queryKey:['workspace', id], queryFn: () => api.get(`/v1/cases/${id}/workspace`), staleTime: 5_000});
useEventStream([`case.updated:${id}`,`query.updated:${id}`], () => qc.invalidateQueries({queryKey:['workspace', id]}));
const etag = ws.data?.etag;   // sent as If-Match on mutations
```
Secondary queries (lazy, Suspense): `/v1/cases/{id}/documents`, `/v1/cases/{id}/audit?limit=5`, `/v1/cases/{id}/queries`, `/v1/cases/{id}/calc/trace` on drawer open.

### 6.2 Role-aware hints
```ts
const can = {
  override: (f: Finding) => hasRole('reviewer') && (f.code.startsWith('identity.') ? hasRole('senior_reviewer') : true),
  submitDecision: hasRole('reviewer'),
  approve: hasRole('approver') || hasRole('senior_reviewer'),
  resolveEscalation: hasRole('senior_reviewer'),
  editConfig: hasRole('admin'),
};
```
UI hides; server enforces; 403 shows "You do not have permission for this action."

### 6.3 Decision form
Fields: outcome (radio: confirm recommendation / adjust / reject / needs info), amount (shown if adjust), reason codes (multi-select from API list, required when amount < recommendation or outcome reject), comment (required for adjust/reject, min 10 chars).
Validation (client, UX-only): reviewer-entered amount ≤ calc payable (server also enforces); amount ≥ 0; max 2 decimals.
Submit flow:
0. Claims where every hard gate passed and payable ≤ `T_auto` are auto-approved by the system: no decision form and no reviewer confirmation task exist for them. The workspace shows an **"Auto-approved by system"** badge with the gate results (identity, authenticity, completeness, calculation, flags), `T_auto` and thresholds version, and the audit link to `decision.auto_approved`. The decision form below is used only for cases the gate did not auto-approve (gate failed, flag raised, payable > `T_auto`, or reject).
1. Click "Submit decision" → confirmation modal summarising outcome, amount and tier ("This goes to 2 approvers").
2. `POST /v1/cases/{id}/decision` with `If-Match`, `Idempotency-Key`.
3. 200 → toast, workspace refreshes (status `awaiting_approval` or final). 409/412 → "Case changed — reload" with changed fields; keep user's draft form values in memory.
4. After final decision workspace goes read-only; actions hidden.

### 6.4 Approval dialog
```ts
const approve = useMutation(({taskId, action, comment}) =>
  api.post(`/v1/approvals/${taskId}/${action}`, {comment}, {idempotent:true}));
```
Client-side UX block: if `task.recommendedBy === me` disable buttons with tooltip "You prepared this decision." (server authoritative).

### 6.5 Evidence highlighting
Evidence `{doc_id, page, bbox:[x0,y0,x1,y1]}` (0..1, origin top-left). Overlay `div` absolutely positioned using rendered canvas size; selecting a finding sets `selectedEvidence` in store → viewer switches doc/page, scrolls to the box, flashes 1 s. No bbox → page jump only. Multiple evidence items cycle with `n`.

### 6.6 SSE → cache invalidation map
| Event | Invalidate |
|---|---|
| `case.updated:{id}` | `['workspace',id]`, `['cases']` |
| `task.opened` / `task.updated` | `['approvals']`, `['home']` |
| `query.updated:{id}` | `['workspace',case]`, `['queries',id]` |
| `escalation.opened` | `['escalations']`, `['home']` |
| `sla.breached` | `['cases']`, `['home']`, toast |
| `approval.requested` | toast (approvers only) |
| `presence` | presence store only |

### 6.7 Idempotency and optimistic locking
Every mutation: `Idempotency-Key: crypto.randomUUID()` created when the dialog opens (reused on retry of the same action); `If-Match: <etag>` from latest workspace.

### 6.8 PII reveal
```ts
const reveal = async () => { const r = await api.post(`/v1/cases/${id}/pii-reveal`, {fields:['full_name']}); setValue(r.values); setTimeout(()=>setValue(null), 60_000); };
```

## 8. Error handling and edge cases
- 401 → silent refresh once, then redirect to login preserving path; 403 → inline "not permitted"; 404 → friendly page; 409/412 → "case changed" dialog with diff of server fields and keep-my-draft option.
- Document viewer: expired presigned URL → refetch once, then error with retry; corrupt PDF → "Cannot render" with download link; very large (200 pages) → virtual pages and lazy thumbnails.
- SSE drop: banner "Live updates paused", polling fallback 30 s; reconnect uses `Last-Event-ID`.
- Two reviewers on one case: presence chip and warning when both edit decision form; server decides on conflict.
- Query text > 1200 chars blocked; paste of > 5000 chars truncated with notice.
- Time: show IST with UTC tooltip; relative times ("in 3 h") update each minute.
- Duplicate submit prevention: buttons disabled while pending; idempotency key.
- Browser back after final decision: workspace read-only; no stale form resubmission (POST via fetch only).
- Step stuck `running` > 20 min: show "Processing is taking longer than expected" with link to ops (admin) or "Re-run" (reviewer).
- Degraded mode: if `/v1/events/stream` fails repeatedly, hide live indicator and rely on manual refresh button.
- Large calc tables: virtualised; export to CSV for senior/admin.
- Accessibility: all actions reachable by keyboard; dialogs trap focus; chips have text labels.
- Localisation: English only (v1); currency format `en-IN` (₹ 1,23,456.00).
- Empty/zero states for every list; error boundaries per pane so one failure does not blank the workspace.
- Session expiry during a long form: draft preserved in memory; after re-login user returns to the same route.
